你现在媒体库最核心的问题其实不是“少几个功能”，而是**资源进入、分类、尺寸规范、使用场景、预览体验没有被统一管理**。尤其你刚才已经确定 Slider、文章封面、正文图片、广告图片都有固定尺寸/比例要求，所以媒体库应该升级成“媒体资产中心”，而不是简单的上传列表。

我建议直接按下面这套设计。

# Nuxt Blog Media Library 媒体库优化设计

## 1. 模块目标

媒体库负责：

```text
上传
分类
文件夹
标签
搜索
筛选
图片尺寸规范
自动生成变体
裁切
Lightbox 预览
引用关系
Alt / Caption
多语言媒体信息
重复文件检测
删除保护
批量操作
存储管理
```

媒体库不应该只是：

```text
上传图片
↓
显示图片列表
```

而应该成为：

```text
Media Asset
    │
    ├── 原图
    ├── 不同尺寸 Variant
    ├── 分类 / 文件夹
    ├── 标签
    ├── Alt / Caption
    ├── 使用位置
    └── 引用关系
```

---

# 2. 你当前存在的三个核心问题

## 2.1 分类乱放

目前如果所有图片都扔到一个 Media Library：

```text
文章图片
封面
Logo
Slider
广告 Banner
Avatar
页面图片
```

很快就会完全失控。

所以必须把：

```text
物理存储
```

和：

```text
逻辑分类
```

分开。

不要靠文件名管理。

---

# 3. 推荐采用「文件夹 + 类型 + 标签」三层组织

## 第一层：Folder

给人看的逻辑文件夹。

例如：

```text
媒体库
├── 文章
├── 页面
├── 轮播图
├── 广告
├── 站点
├── 用户头像
└── 未分类
```

文章下面还可以：

```text
文章
├── 2026
│   ├── 09
│   ├── 08
│   └── 07
```

但不要强制每个用户手动建年月目录。

---

# 4. 第二层：Media Type / Usage Type

系统自动识别或设置：

```text
general
post_content
post_featured
page_content
slider
advertising
avatar
site_logo
site_icon
og_image
```

这些是机器类型。

例如：

```text
Slider 图片
usage_type = slider
```

它可以同时放在：

```text
Folder = 首页轮播
```

里。

# 5. 第三层：Tags

例如：

```text
Nuxt
AI
GPU
Crypto
Homepage
2026
```

三者职责：

```text

→ 系统用途

Tag
→ 横向检索
```

# 9. Grid Thumbnail 必须统一尺寸

这是你现在“图片大小不合适”的一个来源。

媒体库 Grid 不应该：

```text
竖图很高
横图很矮
Logo 很小
```

统一：

```text
thumbnail container
aspect-ratio: 1 / 1
```

内部：

```text
object-fit: cover
```

但有一个例外：

对于：

```text
logo
icon
transparent PNG
SVG
```

可以：

```text
object-contain
```

并用棋盘格背景。

# 10. Thumbnail 不代表原图裁切

```text

```

不要修改原图。

例如：

```text

```

媒体库 Grid：

```text
240 × 240 preview
```

只是缩略图。

# 20. 不要给所有图片生成所有 Variant

这一点很重要。

否则：

```text
一张图片
→ 10 个 Variant
```

长期浪费大量存储。

推荐：

### 基础 Variant

每张图片：

```text
thumbnail
medium
large
```

### Usage-specific Variant

只有被用于：

```text
Slider
Post Featured
OG Image
Avatar
```

时才：

```text
按需生成
```

# 100. 最终冻结规则

### Rule 1

原图永远不因为 Thumbnail / Slider / Card 裁切而被修改。

### Rule 2

不同使用场景必须使用不同 Media Variant。

### Rule 3

Grid 统一 Thumbnail，不展示原始比例导致瀑布式混乱。

### Rule 4

Slider、Featured、Avatar 等固定比例由系统 Preset 控制。

### Rule 5

Lightbox 必须使用 Large / Original，不得使用 Thumbnail。

### Rule 6

Lightbox 最大化到接近整个 Viewport，并支持 Zoom / Fullscreen。

### Rule 7

媒体分类使用：

```text
Folder + Usage Type
```

不要只依靠文件名。

### Rule 8

媒体删除前必须查询引用。

### Rule 9

所有模块统一使用 MediaPicker。

### Rule 10

前端页面不得直接使用 Original 作为 Card / Slider 图片。

---

## 最终建议

你现在媒体库最值得优先重构的不是“加更多按钮”，而是先把下面这一条链做好：

```text
上传
↓
自动归类
↓
生成 Thumbnail
↓
Media Library
↓
统一 Folder / Usage
↓
选到具体业务
↓
按业务比例 Crop
↓
生成对应 Variant
↓
前端使用正确 Variant
↓
Lightbox 使用 Large / Original
```

这样一改，你现在的三个问题：

```text
分类乱放
图片尺寸不统一
Lightbox 太小
```

会一起从根本上解决。

其中我最建议你优先改的是 **`Folder + Usage Type + Media Variant + Crop Editor + Used By + 全屏 Lightbox`** 这六项。尤其 `Variant` 要和你刚才定下的 Slider 规格直接打通，否则以后文章封面、Slider、广告图又会各自重复处理图片。
