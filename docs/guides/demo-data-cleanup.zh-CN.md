# 测试数据清理使用手册（中文）

## 功能用途

后台「设置 → 数据库」提供「一键清理测试数据」。它用于开发、验收和部署前清理本项目明确生成的演示数据与 E2E 测试夹具。

清理前页面会先显示检测数量，并要求管理员二次确认。只有拥有 `settings.edit` 权限的管理员/角色才能执行，接口也会再次校验权限。

## 当前识别范围

当前 MySQL 适配器只匹配以下明确标记：

- 文章 Alias：`demo-*`、`pagination-test-*`
- 广告计划名称：`Demo · *`、`E2E *`
- 由上述广告计划创建的广告创意、翻译和投放关联
- 评论正文以 `E2E ` 开头，或测试邮箱为 `e2e@example.com`
- 媒体文件名以 `demo-banner-` 开头

不会根据“创建时间较早”“标题看起来像测试”等模糊条件删除记录。广告计划关联的订单和支付流水会保留，仅解除广告计划关联，避免破坏财务审计链路。

## 使用步骤

1. 先备份数据库，或在部署前使用临时数据库副本。
2. 使用管理员账号进入后台。
3. 打开「设置 → 数据库」。
4. 查看「检测到」数量，确认范围符合预期。
5. 点击「清理检测到的测试数据」并确认。
6. 清理后刷新文章、广告、媒体和评论列表，确认业务数据仍在。

## 数据库兼容说明

当前清理器只实现并验证了 Laragon MySQL/兼容 MySQL 路径。项目的 PostgreSQL/Supabase 适配尚未完成，不能只切换 `DB_DRIVER` 后假设本功能自动兼容；在其他数据库上接口会返回冲突提示，不执行删除。

当前上线建议：

- 使用 MySQL 8+ 或 Laragon 中已验证的 MySQL 实例。
- 通过 `DB_DRIVER=mysql` 和 `DATABASE_URL`/`DB_*` 配置连接数据库。
- 不要把真实数据库、支付流水和生产媒体库作为演示站数据源。
- PostgreSQL/Supabase 适配完成后，需要新增对应 Repository、迁移、事务测试和清理器测试，才能开放该数据库的清理按钮。

## 安全边界

- 生产站不要打开 `SEED_DEMO`，也不要把公开演示账号连接到生产数据库。
- 清理功能不能替代数据库备份、权限控制、输入校验、富文本清洗和上传安全策略。
- 清理操作不可撤销；如果需要保留证据，请先导出或备份。
- 新增测试数据时应沿用明确前缀或独立 fixture 标记，禁止修改清理器去猜测业务数据。
