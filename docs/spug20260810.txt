接口文档
请求地址
POST https://push.spug.cc/send/<TEMPLATE_CODE>

使用控制台中已创建的通知模板，向模板预设的接收人或分组发送消息。

请求参数
参数	类型	必填	说明
TEMPLATE_CODE	string	是	路径参数，通知模板的编码
JSON 请求体	object	否	属性名与模板变量一致；模板没有变量时可不传
请求示例
curl 'https://push.spug.cc/send/<TEMPLATE_CODE>' \
  -H 'Content-Type: application/json' \

推荐使用 POST + JSON；接口也兼容查询参数和表单数据。

}

先看调试日志
在调试日志中找到对应的接口调用，依次查看：

请求参数：确认平台实际收到的内容。
接口返回：请求未受理时，直接查看 code 和 msg。
推送结果：请求已受理时，查看每个接收渠道的发送状态和说明信息。
接口返回成功只表示请求已受理，最终结果以“推送结果”为准。调试日志只展示近期调用，更早的消息可以到发送记录中查询。

常见失败原因
说明信息已经给出具体原因时，以日志原文为准。下面只汇总不同场景中常见的原因。

接口请求
常见原因：凭证或模板无效、请求参数缺失或格式错误、模板变量缺失、IP 不在白名单、请求频率超限、账户权限受限、内容命中黑名单。

/send 通知与告警
常见原因：未匹配到推送对象、接收组没有有效渠道、模板处于沉默期、触发条件未满足、官方模板变量映射失败、通道余额不足。

/xsend 给自己发消息
常见原因：没有符合条件的个人渠道或默认渠道、App Key 未授权当前渠道、指定渠道未开启或配置无效、消息格式不支持、使用了不支持的短信渠道。

/sms 短信验证码
常见原因：手机号格式错误、验证码或模板变量缺失、未完成实名认证、发送频率超限、短信余额不足、内容审核失败。

/mail 邮件验证码
常见原因：邮箱格式错误或收件人数量超限、scene、code 或 minute 缺失、收件地址已退订或无效、发送频率超限、邮件余额不足。

在通知模板中读取请求参数和嵌套字段。

通知模板使用 ${变量名} 标记动态内容。调用 /send 时，推送助手会从请求参数中读取同名字段，并把模板中的占位符替换成实际值。

变量只属于通知与告警使用的通知模板；短信和邮件验证码接口请按各自官方模板的参数说明调用。

基础变量
假设模板内容为：

服务器 ${server} 的状态为：${status}
请求数据为：

{
  "server": "api-01",
  "status": "CPU 使用率过高"
}
最终消息为：

服务器 api-01 的状态为：CPU 使用率过高
变量名区分大小写。${server}、${Server} 和 ${SERVER} 会被视为三个不同的变量。

对象属性和数组元素
变量支持读取嵌套对象和数组。以下面的请求数据为例：

{
  "id": 20,
  "user": {
    "nickname": "张三丰",
    "age": 26
  },
  "messages": [
    {
      "id": 12,
      "content": "你好"
    },
    {
      "id": 13,
      "content": "在吗？"
    }
  ]
}
模板中可使用的变量包括：

模板变量	读取位置	替换结果
${id}	顶层字段 id	20
${user.nickname}	对象 user 的 nickname	张三丰
${messages[0].id}	数组第 1 项的 id	12
${messages[1].content}	数组第 2 项的 content	在吗？
数组下标从 0 开始。变量路径不存在或名称不一致时，占位符无法得到预期替换；应先检查实际请求数据，再检查模板中的路径。

变量映射
短信、语音和微信公众号等固定内容通道使用官方模板，模板要求的变量名通常是 key1、key2 等固定名称。变量映射可以把这些固定名称映射到业务请求中的字段，调用方不必为了通道模板修改原有数据结构。

例如短信官方模板包含：

您的 ${key1} 发生告警，${key2}，请及时处理！
在通知模板中配置以下映射：

固定变量	映射内容
key1	${ip}
key2	${name} 当前值：${value}%
调用方即可发送：

{
  "ip": "121.199.2.22",
  "name": "CPU 使用率",
  "value": 92
}
最终短信内容为：

您的 121.199.2.22 发生告警，CPU 使用率 当前值：92%，请及时处理！
映射内容同样支持对象路径、数组下标和内置函数。

函数	用途	示例
utc_to_cst(value)	ISO 8601 UTC 时间转中国标准时间	${utc_to_cst(starts_at)}
datetime(value)	时间戳转日期和时间；不传参数时取当前时间	${datetime(trigger_time)}

提取并连接数组
unpack_and_join() 有三种常用写法。

提取对象数组中每一项的同名字段，并使用默认空格连接：

${unpack_and_join(alerts, instance)}
输出：

172.16.26.1 172.16.26.2
指定连接符：

${unpack_and_join(alerts, instance, ; )}
输出：

修改函数表达式后，先用通知模板的“在线测试”检查输出，再更新生产调用。查询发送状态
使用 request_id 查询一次发送请求的通道明细。

/send、/xsend、/sms 和 /mail 成功受理请求后会返回 request_id。使用状态查询接口，可以获取该次请求产生的每一条通道明细。

一个请求可能同时发送到多个手机号、邮箱或机器人，因此查询结果是数组，不是单条状态。

接口地址
POST https://push.spug.cc/request/query
Content-Type: application/json
请求参数
参数	类型	必填	说明
token	string	是	账户开发者 Token，在凭证管理中复制
request_id	string	是	发送接口成功响应中的请求 ID
该接口只接受开发者 Token，不接受 App Key 或模板编码。

请求示例
cURL
curl 'https://push.spug.cc/request/query' \
  -H 'Content-Type: application/json' \
  -d '{"token":"<DEVELOPER_TOKEN>","request_id":"<REQUEST_ID>"}'
Python
import requests

response = requests.post(
    "https://push.spug.cc/request/query",
    json={
        "token": "<DEVELOPER_TOKEN>",
        "request_id": "<REQUEST_ID>",
    },
    timeout=10,
)
print(response.json())

响应字段
字段	类型	说明
target	string	手机号、邮箱、公众号用户或机器人目标
type	string	短信、语音、邮件、微信公众号或群机器人等通道名称
fee	number	本条消息的计费数量，不是人民币金额
status	string	通道处理状态
reason	string	失败、审核或其他补充说明；无说明时为空字符串
状态值
status	含义	处理建议
0	待发送	请求已入队，稍后再次查询
1	发送中	已提交到通道服务商，等待最终结果
2	成功	通道已返回成功；邮件仍可能进入垃圾邮件箱
3	失败	查看 reason 并修正后再发送
4	审核中	等待平台审核结果，不要立即重复提交
发送接口返回 code=200 只表示请求已受理，不代表数组中的每条消息都已经成功。最终结果以本接口或发送记录为准。

常见错误
code	常见 msg	处理方式
400	缺少 token 或 request_id	检查 JSON 字段名和请求体
403	Token 无效或账户已暂停	复制当前开发者 Token，确认账户状态
404	请求记录不存在或已过期	检查 request_id 是否属于当前账户、是否完整
429	IP 限流	停止继续尝试错误 Token，稍后再请求
连续提交无效 Token 会触发调用来源限流。不要通过枚举 Token 或 request_id 探测记录。

查询建议
保存发送响应中的 request_id，不要根据目标和时间反推请求。
对待发送、发送中或审核中状态使用间隔查询，避免紧密轮询。
同一 request_id 可能同时出现成功和失败明细，业务系统应逐条处理。
不确定发送是否已经受理时，先查询原 request_id，不要立即重发，以免产生重复通知。
记录排错信息时保留 request_id、时间和脱敏目标，不要记录完整开发者 Token。查询发送历史
分页查询最近 30 天的短信和邮件记录。

发送历史接口用于分页查询当前账户最近 30 个自然日内的短信和邮件明细，适合业务服务端同步记录或制作内部报表。

该接口不返回语音、微信公众号和群机器人记录；如需查看全部通道，请使用控制台的发送记录。

接口地址
POST https://push.spug.cc/request/history
Content-Type: application/json
请求参数
参数	类型	必填	说明
token	string	是	账户开发者 Token，在凭证管理中复制
type	string	否	sms 或 mail；不传时查询两类记录
start_date	string	否	开始日期，格式 YYYY-MM-DD
end_date	string	否	结束日期，格式 YYYY-MM-DD
page	number	否	页码，默认 1，必须大于 0
page_size	number	否	每页数量，默认 20，范围 1 至 100
该接口只接受开发者 Token，不接受 App Key 或模板编码。

日期规则
不传日期时，默认查询包含今天在内的最近 30 个自然日。
开始和结束日期都不能早于可查询范围。
结束日期不能晚于今天。
开始日期不能晚于结束日期。
接口响应会返回本次实际使用的 start_date 和 end_date。
请求示例
查询最近 30 天邮件
curl 'https://push.spug.cc/request/history' \
  -H 'Content-Type: application/json' \
  -d '{"token":"<DEVELOPER_TOKEN>","type":"mail","page":1,"page_size":20}'
