# ADR 0007：通用架构边界与质量闸门

- 状态：Accepted
- 日期：2026-09-13

## 背景

项目演进中反复出现数据库实现泄漏到业务层、语言包混用、公开 URL 不统一、异步请求竞态、权限只在前端执行和测试无法证明真实行为等问题。单点修复容易在下一个模块重新出现。

## 决策

采用统一的模块契约和分层：页面/组件 → application/domain service → repository contract/context → adapter。Alias、locale、错误、异步生命周期、缓存和测试闸门也作为跨模块契约维护，具体规则见《通用架构设计与开发约束》。

每个新模块先定义 contract，再实现 adapter 和 API/UI；删除兼容层前必须完成调用方扫描、迁移、回归和回滚准备。

## 影响

短期会增加 contract、测试和审查工作；长期可以独立替换 MySQL/PostgreSQL/外部服务，减少混合语言、路由断链、脏状态和不可复现回归。现有业务按模块渐进迁移，不要求一次性重构。
