
我建议这次把命名和 AI 架构一起定下来，因为它们实际上会互相影响：未来 AI Chat 也应该能分析你的 Profile、文章、SEO、商店、评论等模块，而不是只认识“文章”。

## 一、`/author` 我建议改掉

你现在这个页面已经不是“博客作者归档页”，而是：

> **你的公开个人身份页 + 在线简历 + 项目/技能/经历展示页**

所以 `/author` 语义偏窄。

我会在这几个里面选：

| URL | 含义 | 推荐度 |
|---|---|---:|
| `/profile` | 个人主页、职业资料、简历、项目都能包含 | ⭐⭐⭐⭐⭐ |
| `/resume` | 很明确是简历，但太求职化 | ⭐⭐⭐⭐ |
| `/about-me` | 亲切，但和 `/about` 容易混 | ⭐⭐⭐ |
| `/me` | 极简、有个性，但 SEO/语义偏弱 | ⭐⭐⭐ |
| `/author` | 像博客作者归档页 | ⭐⭐ |
| `/cv` | 偏学术/欧洲风格 | ⭐⭐ |

### 我最推荐：`/profile`

导航名称：

```text
Profile
```

中文：

```text
个人主页
```

页面本身可以呈现 Resume 风格。

也就是说：

```text
/profile
```

≠ 社区用户 Profile

而是：

```text
Professional Profile
Personal Resume
Projects
Experience
Skills
Social
Current Focus
```

它比 `/resume` 更耐用。

以后你不仅找工作，还可能展示：

- 开源项目
- 产品
- 技术栈
- 专业方向
- 当前在做什么
- 社交渠道
- 教育经历
- 证书
- 合作方式

`/resume` 就逐渐显得太窄，而 `/profile` 仍然成立。

### 最终建议

冻结成：

```text
/about
→ 关于这个网站

/profile
→ 关于你本人

/contact
→ 联系

/posts
→ 文章
```

侧边栏作者卡 CTA：

```text
View Profile →
```

中文：

```text
查看个人主页 →
```

而不是：

```text
查看作者 →
```

这样整体身份就从“博客作者”升级成“个人站主人”。

# 六、Content AI

分析：

```text
标题是否清楚
摘要是否重复标题
段落是否太长
内容结构
标题层级
重复表达
CTA 是否清楚
信息缺失
语言可读性
内容是否过于冗长
```

例如：

```text
Medium

The introduction repeats much of the page description.

Current:
"Nuxt 4 博客框架起步……"

Suggestion:
Remove the first paragraph or rewrite it as an introduction.
```

Actions：

```text
Review
Apply
Dismiss
```

但 `Apply` 只有当修改的是 CMS Content Schema 时才出现。

# 七、SEO AI

分成两部分。

### Rule Engine

确定性检查：

```text
缺少 title
缺少 description
缺少 H1
多个 H1
canonical 缺失
OG image 缺失
alt 缺失
heading 跳级
title 太长
description 太长
slug 问题
```

这些根本没必要浪费 AI Token。

### AI

负责：

```text
SEO title 是否吸引人
description 是否准确
搜索意图
标题与正文一致性
内部链接机会
内容覆盖不足
关键词语义一致性
```

这样比让 LLM 做全部 SEO 检查更靠谱。

```text
DOM Summary
Layout Metadata
Design Tokens
```



## 最终我建议冻结三个决定

**第一，作者简历页改为 `/profile`。** `author` 留给“作者”语义，Profile 才能自然承载你的经历、项目、技能、教育、证书、社交渠道和 Current Focus。

**第二，A3 Page AI 做“当前页面 Copilot”，但以结构化 Audit/Suggestion 为核心，而不是聊天框。** Rule Engine 负责确定性问题，LLM 负责语义/UI 判断，只允许对 Page Schema 支持的字段产生可 Apply Patch。

**第三，AI Chat 独立成为 AI Assistant。** 它通过 `Scope + Context + Tool Calling + Business Services` 分阶段读取整站数据，可以分析整站，也可以只分析 Posts、Profile、Store 或某个具体页面；默认 Read/Suggest，不给予直接数据库写权限。

这三块组合起来后，你的产品逻辑就非常清楚：

```text
Editor AI
→ 帮我改这一段

Page AI
→ 帮我检查这个页面

AI Assistant
→ 帮我理解、分析整个站或跨模块数据

Site Reports
→ 定期/主动生成系统性检查报告
```

我认为这比把所有 AI 都塞进一个聊天框里要成熟很多。
