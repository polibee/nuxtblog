# Alias 驱动的统一显示名称与文章内容页优化设计

## 1. 背景与目标

当前后台资源、前端导航和多语言页面存在多套名称回退逻辑：有的回退到中文，有的显示 URL，有的直接显示 Alias，导致配置重复、英文界面不一致、导航维护成本高。

本设计建立统一的显示名称标准：

- 中文是默认管理语言，显示中文名称。
- 英文优先显示已填写的英文名称。
- 英文名称为空时显示资源 Alias。
- 没有 Alias 的系统项使用稳定的英文系统标识。
- URL 只用于跳转，不作为用户可见名称。
- 文章标题、正文和摘要继续独立维护，不使用 Alias 代替文章内容。

同时优化文章内容页：正文图片自适应、支持安全的 Markdown/HTML/BBCode 图片 Embed，并移除标题下方的摘要展示。

## 2. 统一显示名称契约

新增共享纯函数 `resolveDisplayLabel`，供服务端 DTO、后台资源定义和前端导航显示使用。

```ts
interface DisplayLabelInput {
  locale: 'zh-CN' | 'en' | string
  defaultLabel: string
  localizedLabel?: string | null
  alias?: string | null
  systemKey?: string | null
}

function resolveDisplayLabel(input: DisplayLabelInput): string
```

解析规则：

```text
中文：中文名称 → Alias → 系统英文标识
英文及其他非默认语言：本地化名称 → Alias → 系统英文标识 → 中文名称
```

实现要求：

- `localizedLabel` 和 `alias` 必须 trim 后再判断是否为空。
- Alias 必须使用已经校验过的稳定标识，不能从 URL 临时截取。
- 不允许返回空字符串；没有任何可用值时由调用方提供固定系统标识。
- 该函数不得访问数据库、路由或浏览器 API，便于单元测试和 SSR 复用。
- 后台编辑器仍允许填写中文名称和英文名称，但英文名称改为可选字段。

## 3. 适用范围

### 3.1 采用 Alias 回退的对象

| 模块 | 中文显示 | 英文缺省显示 | 备注 |
| --- | --- | --- | --- |
| 页眉导航 | 中文菜单名 | Alias | URL 只负责跳转 |
| 页脚导航 | 中文栏目/菜单名 | Alias | 栏目仍支持子菜单 |
| 页面管理 | 页面中文标题 | 页面 Alias | 页面正文不变 |
| 分类、标签 | 中文名称 | 分类/标签 Alias | 用于筛选、导航和列表 |
| 设置模块 | 中文字段名 | 稳定 setting key | 不显示数据库列名 |
| 商品、商城 | 中文商品名 | 商品 Alias | 商品营销文案仍独立维护 |
| 销售、订单、支付 | 中文资源名 | 稳定资源 key | 交易内容和金额不变 |
| 广告、媒体、导航 | 中文名称 | Alias 或系统 key | 便于后台多语言配置 |
| 系统菜单 | 中文系统名称 | 固定英文 system key | 如 `home`、`settings`、`posts` |

### 3.2 不采用 Alias 替代的对象

- 文章标题、正文、摘要和 SEO 文案。
- 评论内容和用户填写内容。
- 广告创意正文、图片文案和链接文本。
- 商品描述、营销标题和付费页面文案。
- 作者个人主页内容和社交渠道名称。

文章的中文和英文翻译继续完全独立：可以只写一种语言，也不要求两种语言一一对应。前端只展示当前语言下已发布的文章翻译。

## 4. 数据与 API 设计

### 4.1 Alias 约束

- Alias 是稳定的公开标识，不因语言切换改变。
- Alias 使用小写字母、数字和短横线，长度和保留字规则沿用现有内容校验。
- 页面、分类、标签、商品等可路由资源必须有唯一 Alias。
- 系统资源使用代码中声明的 `systemKey`，不得依赖 URL 推导。
- 修改已发布资源 Alias 时继续创建旧路径到新路径的 301 记录。

### 4.2 DTO 输出

服务端在返回管理资源和公开导航 DTO 时，提供：

- `label`：按照统一规则解析后的当前语言显示名。
- `defaultLabel`：默认语言名称，供管理端编辑使用。
- `localizedLabel`：当前语言的显式名称，可为空。
- `alias`：稳定资源标识。

客户端不再自行根据 URL、标题或对象字段猜测显示名称，避免后台和前端出现不同结果。

### 4.3 配置表单简化

- 默认语言表单显示中文名称并设为必填。
- 英文名称改为可选，并展示提示：“留空时使用 Alias”。
- 非默认语言暂不强制创建翻译行。
- 资源没有 Alias 时显示系统 key，并在后台提示该项为系统内置标识。
- 保存时服务端仍验证名称长度、Alias 格式和权限。

## 5. 导航行为

导航项目保存结构保持现有 `label + targetEntity + customUrl` 契约，不把 Alias 写入自定义 URL。

- 实体导航：通过目标实体的当前语言名称解析 `label`，URL 由目标实体 Alias 生成。
- 英文翻译缺失：显示目标实体 Alias，仍使用当前语言可用的公开 URL。
- 自定义导航：中文名称必填；英文名称可选；英文缺省使用自定义项的稳定 key 或管理员明确提供的英文标识。
- 页脚栏目：栏目本身使用 group/system key，子菜单遵循实体 Alias 回退规则。
- 菜单删除、禁用和缓存失效继续由导航 Repository 与事件处理，不能只在前端隐藏。

## 6. 文章内容页设计

### 6.1 图片尺寸

- 特色图和正文图片使用不同样式契约。
- 正文图片 `max-width: 100%`，保持原始比例，不允许撑破阅读列。
- 默认设置合理的最大显示高度，超高图片使用 `object-fit: contain`，不裁剪内容。
- 移动端按容器宽度缩放，避免横向滚动。
- 图片具备键盘可访问的预览入口，点击后打开大图。
- 图片样式只作用于文章正文容器，不影响首页卡片、作者卡片和媒体库。

### 6.2 Embed 输入格式

内容解析层支持：

- Markdown：`![说明](https://example.com/image.webp)`
- HTML：`<img src="https://example.com/image.webp" alt="说明">`
- BBCode：`[img]https://example.com/image.webp[/img]`
- 普通 HTTPS 链接：渲染为安全的可点击链接。

处理顺序：

```text
输入内容 → 格式归一化 → 外部地址校验 → 富文本白名单清洗 → 文章渲染
```

安全要求：

- 只允许 HTTPS 图片地址和站内相对地址。
- 拒绝 `javascript:`、`data:`（除非未来单独设计受控 data 图片）、私网回环地址和非图片协议。
- 不自动嵌入任意 iframe 或外部网页。
- 图片 alt、title、链接文本进行长度限制和 HTML 清洗。
- 服务端保存前和公开输出前都必须经过现有白名单清洗流程。

### 6.3 摘要展示边界

- 文章内容页标题下方不再显示摘要。
- 摘要继续用于首页卡片、搜索结果、归档和 RSS 等摘要场景。
- 摘要为空时，列表接口继续从正文首个有效段落生成回退摘要。

## 7. 分阶段实施

1. 新增共享 `resolveDisplayLabel` 与单元测试。
2. 接入前端页眉、页脚和系统导航。
3. 接入页面、分类、标签及导航管理器。
4. 接入设置、商城、销售、订单、支付、广告和媒体后台资源。
5. 统一后台资源 schema 的英文可选字段及提示文案。
6. 优化文章内容页图片样式和大图预览。
7. 新增 Markdown/HTML/BBCode 图片归一化与安全测试。
8. 移除各模块重复的 URL/中文名称回退代码。
9. 执行前台中英文导航、深链、文章独立语言和权限回归测试。

每一阶段都保持旧数据兼容：已有英文名称优先保留，未填写英文名称的资源自动使用 Alias，不要求立即批量补录翻译。

## 8. 验收标准

- 中文导航显示中文名称。
- 英文导航有英文名称时显示英文名称，无英文名称时显示 Alias。
- URL 不再作为可见菜单名称。
- 页面、分类、标签、商城和后台资源遵循同一解析结果。
- 中文/英文文章可独立发布，互不强制匹配。
- 文章内容页不显示标题下摘要。
- 超大正文图片不会撑破内容列，移动端无横向滚动。
- Markdown、HTML、BBCode 图片可安全渲染，危险协议被拒绝。
- 现有权限、301、菜单删除、缓存失效和文章卡片摘要功能不回归。
- `npm run lint`、`npm run typecheck`、`npm test`、`npm run build` 通过。
