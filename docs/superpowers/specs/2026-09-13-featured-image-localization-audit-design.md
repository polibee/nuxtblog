# 特色图片与多语言体系审计及修复设计

**日期：** 2026-09-13  
**状态：** 待审查  
**范围：** 文章特色图片、前后端 UI 多语言、文章 Embed 文案、自动化回归审计

## 1. 背景与问题

当前项目已经具备文章多语言、媒体选择器、公开文章详情页和文章 Embed 基础能力，但仍有两类体验问题：

1. 后台选择文章特色图片后，部分文章详情页或列表页没有生效，编辑已有文章时也可能无法稳定回显。
2. 前后台存在语言包集中、模块文案混用、英文页面出现中文、Embed 固定英文文案等问题。

当前文章字段同时出现 `featuredMediaId`（文章实体）和 `featuredImageId`（翻译字段）两个概念。Repository 读取时虽然兼容两者，但编辑表单、保存接口和公开映射没有形成单一契约，这是特色图片不生效的主要风险点。

## 2. 目标与非目标

### 2.1 目标

- 文章特色图片统一归属于文章实体，后台、Repository、公开 API 使用 `featuredMediaId`。
- 已有文章可以正确回显、替换和清空特色图片。
- 首页、归档页、文章详情页使用同一个 `coverUrl` 映射。
- 前后台语言包按业务模块拆分，避免所有文案堆在一个文件中。
- 英文 UI 不再无提示混入中文；语言缺失时使用明确的回退规则。
- 文章 Embed 卡片文案按当前页面语言展示。
- 建立可重复执行的单元、接口和浏览器回归审计流程。

### 2.2 非目标

- 不自动翻译文章标题、正文、摘要或评论。
- 不把中文文章和英文文章强制建立一一对应关系。
- 不在本阶段迁移数据库到 Supabase/PostgreSQL；当前继续使用 Laragon MySQL。
- 不重做侧边栏作者卡片、文章作者卡片或全站导航视觉结构。
- 不开放任意网页 iframe；Embed 仍只处理安全的外部 HTTPS 链接和图片格式。

## 3. 统一领域契约

### 3.1 特色图片字段

文章实体的公开契约如下：

```ts
interface PostRecord {
  featuredMediaId: number | null
}

interface PublicPostSummary {
  coverUrl: string | null
}
```

规则：

- 新建和更新只接受顶层 `featuredMediaId`。
- `post_translations.featured_image_id` 不再作为新数据写入入口。
- 读取旧数据时允许使用翻译字段作为兼容回退，但必须记录为迁移兼容逻辑。
- `coverUrlFor(featuredMediaId)` 是唯一公开图片 URL 解析入口。
- 媒体不存在、文件不可读或记录被删除时返回 `null`，不能让文章详情失败。

### 3.2 管理表单回显

文章编辑 API 返回的记录必须包含顶层 `featuredMediaId`。媒体选择器加载已有记录时：

1. 先根据 `featuredMediaId` 请求当前媒体详情。
2. 将已选媒体合并到选择器本地集合，即使它不在当前分页中也能显示。
3. 点击清除时提交 `featuredMediaId: null`。
4. 提交期间禁用重复保存，保存成功后刷新资源记录。

### 3.3 多语言内容边界

- UI 文案：进入模块化 UI 语言包。
- 页面、导航、分类、标签和系统资源名称：使用统一的中文名称 / 英文名称 / Alias 回退规则。
- 文章标题、正文、摘要、SEO 文案和广告创意：继续由内容编辑者分别维护。
- 文章 Embed 的展示按钮和说明属于 UI 文案，不应永久写入某个语言版本的正文 HTML。

## 4. 多语言语言包设计

### 4.1 目录结构

将当前集中式字典逐步拆分为模块包，并保留一个聚合入口：

```text
app/i18n/
├── locales/
│   ├── zh-CN/
│   │   ├── common.ts
│   │   ├── admin.ts
│   │   ├── posts.ts
│   │   ├── comments.ts
│   │   ├── advertising.ts
│   │   ├── settings.ts
│   │   ├── commerce.ts
│   │   ├── media.ts
│   │   └── ai.ts
│   └── en/
│       ├── common.ts
│       ├── admin.ts
│       ├── posts.ts
│       ├── comments.ts
│       ├── advertising.ts
│       ├── settings.ts
│       ├── commerce.ts
│       ├── media.ts
│       └── ai.ts
└── index.ts
```

实际迁移必须保留现有 `t()` 调用兼容性，先移动 key，再删除重复 key，避免一次性重写所有组件。

### 4.2 Key 命名

统一使用模块前缀：

```ts
t('posts.actions.publish')
t('comments.actions.reply')
t('advertising.status.pending')
t('settings.fields.siteDescription')
t('common.actions.openLink')
```

禁止新增：

- 模板内直接写中文或英文业务文案。
- 同一个状态在不同模块使用不同 key 表达。
- 用 URL、数据库字段名或中文文本作为翻译 key。

### 4.3 回退规则

- 当前语言存在翻译：使用当前语言。
- 当前语言缺失，默认语言存在：使用默认语言，并记录开发期缺失 key。
- 两种语言都缺失：使用稳定的系统标识，不显示 `undefined` 或空白。
- 英文资源名称：英文名称 → Alias → 系统英文标识。
- 中文资源名称：中文名称 → Alias → 系统标识。

文章内容不采用 UI 文案回退规则；没有英文文章翻译时，英文文章列表不显示该中文文章。

## 5. 后端错误与返回值

后端业务错误采用稳定 code，客户端负责本地化：

```ts
{
  code: 'POST_FEATURED_MEDIA_NOT_FOUND',
  params: { mediaId: 12 }
}
```

HTTP 语义保持：

- 未登录：401
- 无权限：403
- 参数校验失败：422
- 业务冲突：409
- 外部服务或数据库不可用：503

服务端日志保留技术上下文，响应不泄露 SQL、密码、内部路径或密钥。

## 6. Embed 多语言与统一展示

文章正文中的外部 HTTPS 链接统一转换为通用 Embed 数据结构，视觉上采用“左侧网站名称、右侧跳转按钮”：

```text
┌──────────────────────────────┐
│  ↗  github.com       打开链接 ↗ │
└──────────────────────────────┘
```

规则：

- GitHub、X 和其他网站使用同一通用卡片结构，不再存在 Provider 专属视觉分支。
- 数据库存储的历史 Provider 卡片在读取时转换。
- 按钮文案由当前页面 locale 决定：中文“打开链接”，英文“Open link”。
- 卡片不显示完整 URL。
- 正文中的独立 URL 使用块级卡片；句子中的 URL 使用紧凑型行内卡片。
- Markdown、HTML `img`、BBCode 图片继续作为图片处理。
- 只允许 HTTPS 或站内相对媒体路径；禁止 javascript、data、任意 iframe 和脚本执行。

实现上不把本地化文案永久写进正文 HTML。解析器应输出可识别的 Embed 标记，展示层根据 locale 映射按钮文本；历史 HTML 只做兼容转换。

## 7. 自动化审计计划

### 7.1 文章与媒体

- 单元测试：特色图片字段解析、清空、旧字段回退。
- Repository 测试：创建、更新、读取和删除文章时的特色图片映射。
- API 测试：后台保存后返回顶层 `featuredMediaId`。
- 浏览器测试：文章编辑选择图片、保存、刷新、替换、清空。
- 公开页测试：首页、归档、详情的 `coverUrl` 一致。

### 7.2 多语言

- 语言包 key 对齐测试：zh-CN 与 en 必须拥有相同 key 集合，允许显式标记的暂缺项。
- 组件扫描：检测新增业务硬编码文案。
- SSR 测试：初次请求的语言、标题、导航和按钮必须一致。
- 切换测试：切换语言后 URL、文章列表、导航、页脚和 Embed 文案同步更新。
- 内容隔离测试：中文文章不会错误出现在英文文章列表，反之亦然。
- Alias 回退测试：英文名称为空时显示 Alias，不显示中文名称。

### 7.3 模块回归

逐模块覆盖：

1. 文章、页面、分类、标签、导航。
2. 评论、友链、通知、媒体。
3. 设置、用户、权限、账户。
4. 商品、订单、支付、广告。
5. AI、统计、导出和错误页。

每个模块至少验证列表、详情、创建、编辑、删除或禁用、空状态、权限错误、校验错误和语言切换。

### 7.4 质量门禁

```bash
npm run lint
npm run typecheck
npm test -- --run
npm run build
```

当前项目没有独立的 Playwright npm script。若需要浏览器自动化，将新增可重复的 `tests/e2e` 流程和 npm script，不替代现有 Vitest 测试。

## 8. 实施顺序

### 阶段 A：特色图片契约修复

统一字段、修复编辑回显、补 API/Repository/公开页测试，确认 MySQL 链路稳定。

### 阶段 B：语言包拆分

建立聚合入口，按模块迁移 key，优先处理公共壳层、文章、设置、导航、评论和广告。

### 阶段 C：后端错误与 Embed 本地化

统一错误 code、Embed 标记和 locale 展示，处理历史卡片兼容。

### 阶段 D：全模块自动化审计

按模块执行回归，修复首个相关错误后再进入下一个模块，最后执行全量质量门禁。

## 9. 风险与回滚

- 特色图片字段：保留旧字段只读回退，确认历史数据迁移后再移除。
- 语言包拆分：保留旧聚合 key 映射，任何模块迁移失败可单独回退，不回滚其他模块。
- Embed：保留历史 HTML 转换器，解析失败时显示安全的普通文本，不阻塞文章正文。
- 多语言缺失：开发环境报告缺失 key，生产环境使用明确回退，不输出空白 UI。
- 每个阶段独立提交并执行对应测试，禁止用关闭类型检查或放宽清洗规则掩盖失败。

## 10. 验收标准

- 后台设置特色图片后，文章详情、首页和归档都能显示同一图片。
- 编辑已有文章可以看到当前特色图片，替换和清空均立即生效。
- 文章正文中所有外部 HTTPS URL 按统一网站卡片显示，左侧是网站名称，右侧是本地化跳转按钮。
- 前后台主要模块不再出现无意的中英文混排。
- 中文和英文内容按内容语言隔离，文章不被错误自动翻译。
- Alias、UI 语言包、后端错误 code 和 Embed 文案有统一标准。
- `npm run lint`、`npm run typecheck`、`npm test -- --run` 和 `npm run build` 全部通过。
